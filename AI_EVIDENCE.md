# AI-Native Project Evidence

> This document is an evidence-planning document. It must contain only facts that can be independently verified.

## Purpose

The project is intended to demonstrate technical leadership and innovation through an open-source AI-native engineering project.

The evidence should show:

1. what was built
2. what is technically distinctive
3. what the author personally contributed
4. how the work was evaluated
5. whether other people use, reference or contribute to it

## Evidence categories

### Technical contribution

Potential evidence:

- GitHub commit history
- pull requests
- architecture decisions
- implementation history
- tests
- security changes
- release history

### Innovation

Potential evidence:

- AI-native methodology
- documented human/AI workflow
- evaluation framework
- reproducible experiments
- model comparisons
- benchmark results

### Open-source impact

Potential evidence:

- stars
- forks
- issues from external users
- external pull requests
- contributors
- integrations
- downloads/releases
- community references

### External recognition

Potential evidence:

- independent technical articles
- citations
- conference/community references
- third-party project references
- independent reviews

### Personal leadership

Keep a dated record of:

- architectural decisions
- design proposals
- roadmap decisions
- review decisions
- major security decisions
- public technical communication

## Evidence hygiene

Do not:

- inflate metrics
- count self-generated activity as independent recognition
- present planned work as completed
- claim production adoption without evidence
- claim benchmark improvements before measurement

## Suggested evidence log

```text
Date:
Repository version:
Contribution:
Why it mattered:
Evidence URL:
Independent validation:
Measured result:
```

## Global Talent positioning

The project should be presented as one part of a broader professional record.

The strongest narrative is not:

> "I used AI to write a project."

It is:

> "I developed and publicly documented an AI-native approach to software engineering, demonstrated it through an open-source business-intelligence system, and created measurable technical and community evidence around the work."

That statement should only be used when the supporting evidence exists.
