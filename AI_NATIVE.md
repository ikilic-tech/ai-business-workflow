# AI-Native Software Engineering

## Purpose

This document defines what **AI-native** means in this project.

The term should not mean simply "code was generated by AI."

The project uses AI as a first-class capability across both the product and the engineering lifecycle.

## AI-assisted vs AI-native

### AI-assisted

```text
Human designs
    ↓
Human codes
    ↓
AI assists
```

### AI-native

```text
Human defines problem
        ↓
AI explores alternatives
        ↓
Human selects architecture
        ↓
AI implements
        ↓
Automated validation
        ↓
AI assists review/debugging
        ↓
Human approves
        ↓
CI/CD
        ↓
Measurement
        ↓
Feedback
```

## Two AI layers

### 1. AI as a product capability

The application uses AI to produce:

- customer risk assessments
- activity intelligence
- opportunity analysis
- recommended actions
- business process optimization

### 2. AI as an engineering capability

AI is used during:

- planning
- architecture exploration
- implementation
- test generation
- debugging
- refactoring
- security review
- documentation

## Human responsibility

AI does not own the final engineering decision.

Humans remain responsible for:

- requirements
- architecture
- security decisions
- business correctness
- validation
- release approval

## Engineering workflow

For each substantial feature:

1. Define the problem.
2. Write acceptance criteria.
3. Ask AI to explore implementation alternatives.
4. Select the architecture as the human engineer.
5. Implement iteratively with AI assistance.
6. Build and run tests.
7. Review generated code.
8. Perform security analysis.
9. Refactor where necessary.
10. Record important decisions.
11. Run CI.
12. Measure the result.

## Reproducibility

When practical, record:

- model/provider
- relevant prompts/instructions
- input dataset
- output schema
- code version
- evaluation method
- test result
- timestamp

Do not commit secrets or private data.
