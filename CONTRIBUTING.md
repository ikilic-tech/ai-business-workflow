# Contributing

Thank you for contributing.

## Before opening an issue

Search existing issues first.

For feature proposals, describe:

- problem
- proposed solution
- expected user benefit
- alternatives considered
- testing strategy

## Pull requests

Keep PRs:

- focused
- reviewable
- tested
- documented where behaviour changes

Before submitting:

```bash
dotnet build
dotnet test
```

## AI-assisted contributions

AI-assisted contributions are welcome.

Contributors remain responsible for:

- understanding submitted code
- validating generated code
- respecting licenses
- protecting secrets
- adding tests
- reviewing security implications

AI-generated code should not be submitted without human review.

## Commit quality

Prefer commits that represent one coherent change.

Examples:

```text
feat: add opportunity evaluation dataset
test: add customer risk regression cases
docs: document AI-native workflow
security: add prompt injection regression tests
```

## Data policy

Do not submit:

- real customer data
- credentials
- API keys
- private business information
- proprietary datasets

Use synthetic or appropriately licensed data.

## Questions

Open a GitHub issue for questions or proposals.
